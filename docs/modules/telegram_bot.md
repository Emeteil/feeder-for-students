# Модуль TelegramBot

`TelegramBot` связывает прошивку ESP32 с Telegram Bot API по HTTPS.
Модуль настраивает соединение, опрашивает Telegram и передаёт входящие
текстовые сообщения в обработчик. Точка расширения для логики бота —
`HandleMessage()` в [telegram_bot.cpp](../../src/modules/telegram_bot/telegram_bot.cpp).

## Библиотека и транспорт

`AsyncTelegram2` формирует запросы к Bot API и разбирает ответы Telegram.
Она принимает экземпляр `WiFiClientSecure`, который обеспечивает
TLS-соединение, и возвращает обновления в виде `TBMessage`. В нём доступны,
например, `text`, `chatId`, `messageID` и `sender.id`. Используется форк, который поддерживает другой хост и префикс пути запроса.
PlatformIO устанавливает зависимость при сборке. В Arduino IDE установите
её вручную. [Конфигурация PlatformIO](../../platformio.ini)

## Настройка

1. Если локального конфига ещё нет, скопируйте
   [config_local.h.example](../../src/core/config_local.h.example) в
   `src/core/config_local.h`.
2. Задайте `WIFI_SSID`, `WIFI_PASSWORD` и `TELEGRAM_BOT_TOKEN`.
   Храните токен в локальном конфиге.
3. Выберите маршрут подключения. Для прямого подключения к Telegram
   уберите определения `TELEGRAM_RELAY_HOST` и `TELEGRAM_CORS_PROXY_HOST`.
   Для релея укажите его хост в `TELEGRAM_RELAY_HOST`. Для прокси задайте
   его хост в `TELEGRAM_CORS_PROXY_HOST` и префикс пути в
   `TELEGRAM_CORS_PROXY_PREFIX`. Если заданы оба хоста, модуль использует
   хост прокси.

## Публичный API и опрос

- `TelegramBot::Init()` вызывается один раз из `App::Init()`. Он
  настраивает TLS-клиент, маршрут, токен и интервал запросов `getUpdates`
  в 500 мс.
- `TelegramBot::Update()` вызывается на каждом проходе основного цикла
  через `App::Update()`. Пока `State.wifiConnected` равен `false`, модуль
  сбрасывает признак запуска и выходит. При доступном Wi‑Fi он вызывает
  `bot.begin()`, если бот ещё не запущен. Между попытками проходит
  не менее 5000 мс.
- После успешного `begin()` модуль считывает и пропускает входящие
  обновления, чтобы разобрать накопившуюся очередь.
- Модуль вызывает `bot.getNewMessage(msg)` с интервалом не менее 50 мс
  по таймеру `millis()`. Этот вызов продвигает опрос и возвращает тип доступного
  обновления. `MessageNoData` означает, что в этом проходе обновления
  нет. После разбора очереди `MessageText` передаётся в `HandleMessage()`.

## События

Пока модуль не публикует события и не подписывается на `EventBus`.

## Поля AppState

Модуль читает `State.wifiConnected`, чтобы запускать опрос при доступном
Wi‑Fi.

## Известные ограничения

- Библиотека ведёт обмен через повторные вызовы из основного цикла.
  `begin()` может задержать цикл при установлении TLS-соединения и
  запросе `getMe`. `getNewMessage()` может задержать цикл при
  переподключении и чтении HTTP-заголовков или тела ответа. Лимит в
  1000 мс в библиотеке относится только к чтению тела. Таймер модуля
  ограничивает частоту вызовов. Худшая задержка на плате с прокси
  требует измерения.
- Сейчас используется `client.setInsecure()`. TLS шифрует трафик,
  проверка сертификата сервера отключена.

## Как использовать обработчик

Добавляйте обработку текста в `HandleMessage(const TBMessage &msg)`.
Например, ответ в чат, откуда пришло сообщение, отправляется так.

```cpp
SendReply(msg, "Сообщение получено");
```

`SendReply()` вызывает `bot.sendMessage()` и пишет предупреждение в лог,
если библиотека вернула `false`. `sendMessage()` берёт ID чата из
`msg.chatId`. Ответы отправляются как обычный текст. По умолчанию вызов
передаёт запрос TLS-клиенту и возвращается без ожидания ответа Telegram.
Ответ сервера библиотека разбирает при дальнейшем опросе.
