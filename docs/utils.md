# Общие утилиты (`src/utils/`)

Папка для переиспользуемого кода, который нужен сразу нескольким
модулям, но сам не является модулем: никакого `Init()`/`Update()`,
никакой подписки на `EventBus`, просто функции/обёртки, которые можно
`#include` откуда угодно. Если бы `src/core/` не было — `src/utils/`
всё равно существовало бы в любом проекте: это просто "библиотека
мелких инструментов", а `core/` — именно наша архитектура (пины,
конфиг, `AppState`, `EventBus`).

Когда класть сюда, а не в конкретный модуль: если кодом реально
пользуются (или скорее всего будут пользоваться) два и более модуля —
кладите в `utils/`, чтобы не копипастить. Если нужно только одному
модулю — пусть живёт в его `.cpp`, не усложняйте раньше времени.

## Что сейчас есть

### `UnsafeEeprom` (`unsafe_eeprom.h`/`.cpp`)

Тонкая обёртка над стандартным `EEPROM.h` для ESP32. На ESP32 это не
отдельная физическая микросхема EEPROM, а её эмуляция поверх flash —
отсюда и реальные ограничения ниже.

**Почему "Unsafe" в названии — не для красоты:**

1. **Flash изнашивается.** Ресурс перезаписи — порядка 100 000 циклов
   на сектор. Если вызывать `Commit()` на каждой итерации `loop()` —
   можно "убить" память за часы-дни работы. Коммитьте только когда
   значение реально изменилось, и старайтесь не чаще, чем раз в
   несколько секунд (дебаунс/аккумулируйте изменения и сохраняйте
   пачкой).
2. **Нет проверки типа и границ.** `Write<T>(address, value)` просто
   кладёт `sizeof(T)` байт по указанному адресу — если два модуля
   случайно используют один и тот же `address` под разные типы или с
   перекрытием диапазонов, данные тихо испортятся без единого
   предупреждения. Адреса обязаны согласовывать между собой сами
   модули — заведите единый список адресов (например, прямо здесь,
   в этом файле, по мере использования) и не изобретайте свои.
3. **Без `Commit()` ничего не сохранится.** `Write()` пишет только в
   буфер в RAM — при перезагрузке или отключении питания без
   явного `Commit()` всё потеряется.

**Использование:**

`Init()` вызывается РОВНО ОДИН РАЗ за всю прошивку — из `App::Init()`
в `src/app/app.cpp`, до `Init()` модулей-пользователей (так же, как
там уже вызывается `EventBus::Init()`). Не вызывайте `Init()` из
своего модуля: если так сделают два модуля — второй вызов
переинициализирует буфер и может задать другой `sizeBytes`, а кто из
модулей окажется этим "вторым", зависит от порядка в `app.cpp`.
Нужно больше места под хранение — увеличьте `sizeBytes` в этом одном
вызове в `app.cpp`, не добавляйте свой собственный `Init()`.

```cpp
// src/app/app.cpp
UnsafeEeprom::Init(512); // один раз, размер под все модули сразу

// в любом модуле-пользователе, после этого:
#include "../../utils/unsafe_eeprom.h"

UnsafeEeprom::Write(0, someUint32Value);
UnsafeEeprom::Commit();                     // только когда значение реально изменилось
uint32_t v = UnsafeEeprom::Read<uint32_t>(0);
```

**Реестр адресов** (чтобы никто не занял чужой адрес — дополняйте по
мере использования):

| Адрес | Тип       | Кто использует | Что хранит |
|-------|-----------|-----------------|------------|
| —     | —         | —               | свободно   |

## Как добавить свою утилиту

1. `src/utils/<name>.h` (+ `.cpp`, если нужна реализация не в заголовке).
2. Без классов, без `Init()`/`Update()` — просто функции в
   `namespace <Name>`, как везде в проекте.
3. Если у утилиты есть реальные риски/ограничения (как у
   `UnsafeEeprom`) — называйте это явно в самом имени и описывайте их
   прямо в заголовке файла, не прятать в комментарий внизу.
4. Опишите здесь, в этом файле, что утилита делает и как её использовать.
