# Документация проекта

Эта папка — общее место для документации, которую пишут участники проекта
друг для друга. Если вы что-то узнали/настроили/придумали и это будет полезно
другим — записывайте сюда, а не только рассказывайте в чате.

## Что где искать/писать

- **[architecture.md](architecture.md)** — как устроена прошивка целиком:
  модули, EventBus, AppState. Читать всем перед тем, как начать писать код.
  Меняется редко и только по согласованию с лидом/мейнтейнерами (это
  "правила игры" для всех).
- **`modules/<название>.md`** — документация конкретного модуля
  (`src/modules/<название>/`): что он делает, какие события
  публикует/слушает, какие пины и библиотеки использует, что ещё не готово.
  Пишет и обновляет **владелец модуля** — это его ответственность, как
  комментарии в коде, только для людей, а не для компилятора.
  Используйте [modules/_template.md](modules/_template.md) как шаблон:
  скопируйте файл в `docs/modules/<name>.md`, заполните.
- Всё остальное (протоколы, схемы подключения, заметки по железу, гайды) —
  добавляйте новые `.md` файлы сюда же, по смыслу. Если не знаете куда
  положить — спросите в чате или у лида.

## Как писать документацию

- Markdown, без изысков — заголовки, списки, таблицы, блоки кода.
- Пишите проще, чем кажется нужным. Другой участник может не знать того,
  что знаете вы — расшифровывайте сокращения при первом использовании.
- Документация правится через тот же git-процесс, что и код: ветка → коммит →
  Pull Request (см. корневой [README.md](../README.md), раздел "Git и
  GitHub"). Да, даже для одной строчки в `.md` файле.
- Не бойтесь, что документация "неидеальна" — она живой черновик, поправить
  всегда можно новым PR.
