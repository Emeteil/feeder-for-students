# Кормушка для студентов

Автомат для выдачи снеков студентам за решение учебных задач/задач на
логику. Пользователь взаимодействует через сенсорный экран и/или
телеграм-бота, а один микроконтроллер (ESP32) отвечает сразу за UI на
экране, сеть/бота и механику выдачи — единая прошивка.

Этот README — точка входа для всех участников проекта: как поставить
окружение, как собрать и прошить, как устроен код и как мы работаем с
git/GitHub. Если чего-то не хватает — дополняйте (см. [Документация
проекта](#документация-проекта)).

## Архитектура

Код разложен на независимые модули (`src/modules/<name>/`), каждый —
`namespace` с `Init()`/`Update()`, без классов и ООП-паттернов —
осознанно просто, чтобы было доступно тем, кто только начал изучать
C/C++. Модули не знают друг о друге напрямую: общаются через общую
событийную шину (`EventBus`) и общее состояние (`AppState`). Это и
есть тот самый общий API для взаимодействия, общий список событий, к которому
любой модуль может подключиться, не трогая код остальных.

**Подробно, с примерами и объяснением "почему так" — в
[docs/architecture.md](docs/architecture.md). Прочитайте перед тем, как
начать писать свой модуль.**

## Структура репозитория

```
feeder-for-students/
├── feeder-for-students.ino     # точка входа: setup()/loop() → App
├── platformio.ini              # конфигурация PlatformIO
├── justfile                    # команды build/upload/monitor и т.п.
├── docs/                       # документация проекта, см. ниже
└── src/
    ├── core/                   # общее для всех модулей: пины, конфиг, состояние, EventBus
    ├── app/                    # сборка модулей в прошивку (App::Init/Update)
    └── modules/                # сами модули: display, dispenser, sensors, connectivity, telegram_bot, power
```

## Быстрый старт

Если окружение уже настроено (см. [Установка окружения](#установка-окружения)
для первого раза):

```sh
git clone <URL-репозитория>
cd feeder-for-students
cp src/core/config_local.h.example src/core/config_local.h
# откройте config_local.h и впишите свои Wi-Fi/токен бота (для локальных тестов)

pio run -t upload      # или just upload — соберёт и прошьёт плату
pio device monitor -b 115200   # или just monitor
```

Дальше — вопрос вкуса: тот же проект можно открыть и в Arduino IDE (см.
ниже).

## Arduino IDE vs PlatformIO

У нас в команде разный опыт, поэтому проект специально настроен так,
чтобы **собираться и прошиваться и тем, и другим способом** — выбирайте
тот, что удобнее лично вам.

CI на каждый PR проверяет сборку только через PlatformIO (см.
[CI](#ci)) — так надёжнее и быстрее, чем гонять ещё и Arduino CLI на
каждый коммит. Это значит, что Arduino IDE-путь CI **не защищает**: если
пишете/собираете в Arduino IDE, периодически (и обязательно перед
PR, если меняли структуру файлов/`#include`/добавляли библиотеку)
проверяйте, что скетч всё ещё открывается и собирается именно в
Arduino IDE — своими руками, CI за вас это не сделает.

| | Arduino IDE | PlatformIO |
|---|---|---|
| Порог входа | Ниже, привычный интерфейс из туториалов на YouTube | Выше, обычно через расширение VS Code |
| Библиотеки | Ставятся вручную через Library Manager, версии не фиксируются в репозитории (у каждого может стоять своя версия) | Версии библиотек фиксируются в `platformio.ini` (`lib_deps`) — одинаково у всех и в CI |
| Несколько файлов/папок | Компилирует `.cpp`/`.h` из подпапок скетча, **но окно IDE показывает вкладками только файлы из корня скетча** — файлы в `src/modules/...` не появятся как вкладки, открывайте/редактируйте их через "Show Sketch Folder" в обычном файловом менеджере или в другом редакторе | Полноценное дерево файлов проекта, как в любой IDE |
| Пути `#include` | Ищет только относительно файла, который делает `#include` (поэтому в проекте везде используются относительные пути вида `"../../core/pins.h"`, а не просто `"pins.h"`) | То же самое, но плагин/интеллисенс обычно удобнее показывает структуру |
| Настройки платы/порта | Через меню Tools каждый раз (не хранится в репозитории) | Хранится в `platformio.ini`, одинаково у всех |
| CI/автоматизация | Не проверяется автоматически в этом проекте (см. предупреждение выше) | Проверяется в CI на каждый PR |
| Тесты/несколько окружений (разные платы и т.п.) | Не поддерживает | Поддерживает нативно |

**Итог:** если вы только начинаете и хотите минимум трения — берите
Arduino IDE, но помните про особенность с подпапками выше. Если
привычны к VS Code или планируете часто пересобирать/переключать
конфигурацию — берите PlatformIO. Оба варианта — полноправные, не
"второй сорт".

## Установка окружения

### Git

- **Windows:** скачайте с [git-scm.com](https://git-scm.com/download/win)
  либо `winget install --id Git.Git -e --source winget`.
- **Linux (Debian/Ubuntu):** `sudo apt update && sudo apt install git`
  (для других дистрибутивов — свой пакетный менеджер, пакет тоже
  называется `git`).
- **WSL:** ровно те же команды, что и для Linux, внутри дистрибутива WSL.

После установки один раз настройте себя:
```sh
git config --global user.name "Имя Фамилия"
git config --global user.email "you@example.com"
```
`user.email` укажите тот же, что привязан к вашему аккаунту на GitHub
(или любой из адресов, добавленных в `Settings → Emails`) — иначе
коммиты запушатся, но GitHub не свяжет их с вашим профилем (не будет
аватарки/ссылки на профиль, коммит не засчитается в ваш вклад).

На Windows (вне WSL) дополнительно рекомендуется:
```sh
git config --global core.autocrlf true
```
это избавит от постоянных "весь файл изменён" из-за разных окончаний строк (CRLF/LF) между Windows и остальными.

### Вариант A: Arduino IDE

1. Скачайте и установите Arduino IDE (2.x) с официального сайта
   [arduino.cc/en/software](https://www.arduino.cc/en/software).
2. Добавьте поддержку плат ESP32: `File → Preferences → Additional
   Boards Manager URLs`, вставьте:
   ```
   https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
   ```
3. `Tools → Board → Boards Manager`, найдите `esp32` (издатель Espressif
   Systems), установите.
4. Откройте `feeder-for-students.ino` — Arduino IDE сама откроет всю
   папку проекта как скетч.
5. `Tools → Board` выберите вашу плату (обычно `ESP32 Dev Module`,
   уточните у того, кто закупал конкретную плату).

### Вариант Б: PlatformIO

Рекомендуемый способ — VS Code + расширение:

1. Установите [VS Code](https://code.visualstudio.com/).
2. Установите расширение **PlatformIO IDE** из маркетплейса VS Code.
3. Откройте папку `feeder-for-students` в VS Code — расширение само
   подхватит `platformio.ini`, кнопки Build/Upload/Monitor появятся в
   нижней панели.

Либо через CLI (без VS Code), кроссплатформенно (Windows/Linux/WSL):
```sh
pip install -U platformio
pio run                 # сборка
pio run -t upload       # прошивка
pio device monitor -b 115200
```

### `just` (опционально, но удобно)

[`just`](https://github.com/casey/just) — просто короткие алиасы для
частых команд (`just build`, `just upload`, `just monitor`, см.
[justfile](justfile)). Не обязателен — все команды можно выполнять и
напрямую через `pio`/`arduino-cli`.

- **Windows:** `winget install --id Casey.Just` (или `scoop install
  just`, или `choco install just`).
- **Linux/WSL:** `cargo install just` (если стоит Rust), либо пакет
  `just` из вашего пакетного менеджера, либо готовый бинарник со
  страницы релизов [github.com/casey/just](https://github.com/casey/just).

### Драйвер USB-платы

Платы ESP32 обычно используют USB-UART мост CP2102 или CH340. На
Windows 10/11 драйвер часто ставится автоматически при подключении
платы. Если плата не появляется в диспетчере устройств/списке портов —
поставьте драйвер с официального сайта производителя чипа (Silicon
Labs — для CP210x, WCH — для CH340).

### Если работаете в WSL

Git, редактор кода, чтение документации — прекрасно работают в WSL.
Но **WSL2 по умолчанию не видит USB-устройства Windows напрямую**, а
прошивка платы идёт именно по USB. Два варианта:

1. Проще: ставьте Arduino IDE/PlatformIO нативно на Windows и
   прошивайте оттуда, а WSL используйте только для git/редактирования
   (гибридный вариант, так тоже можно).
2. Либо настройте проброс USB-устройства в WSL через `usbipd-win`
   (официальная документация Microsoft: [learn.microsoft.com/windows/wsl/connect-usb](https://learn.microsoft.com/windows/wsl/connect-usb)).

## Библиотеки

**PlatformIO** — добавьте библиотеку в `platformio.ini`, в `lib_deps`
(секция `[common]`):
```ini
lib_deps =
    bodmer/TFT_eSPI@^2.5.43
```
Формат: `автор/Имя библиотеки@^версия`. Точное имя и версию смотрите на
[registry.platformio.org](https://registry.platformio.org). PlatformIO
сам скачает и соберёт библиотеку при следующей сборке — версия
зафиксирована и одинакова у всех в команде и в CI.

**Arduino IDE** — `Sketch → Include Library → Manage Libraries...`,
найдите по имени, `Install`. Для библиотек не из менеджера — `Sketch →
Include Library → Add .ZIP Library`.

**Важно:** если добавляете библиотеку — добавьте её **в оба места**
(и в `platformio.ini`, и через Library Manager себе локально), а в PR
укажите, что участникам с Arduino IDE тоже нужно доставить эту
библиотеку вручную. Иначе проект будет собираться только у тех, кто
пользуется тем же инструментом, что и вы — а CI как раз и проверяет
оба варианта (см. [CI](#ci)).

## Прошивка платы

**PlatformIO:**
```sh
pio run -t upload                        # автоопределение порта
pio run -t upload --upload-port COM5     # если автоопределение не сработало (Windows)
pio run -t upload --upload-port /dev/ttyUSB0   # Linux/WSL
```
или `just upload` (порт по умолчанию из `platformio.ini`).

**Arduino IDE:**
1. `Tools → Port`, выберите порт платы.
2. `Sketch → Upload` (или `Ctrl+U`).

Если заливка зависает на `Connecting....` — на многих платах ESP32
нужно зажать кнопку `BOOT` на плате в момент начала заливки (отпустить,
когда пошла загрузка).

## Блокирующие операции

Один микроконтроллер отвечает сразу за экран, сеть и механику — поэтому
`delay()` и другие блокирующие вызовы **под запретом** в коде модулей:
пока код "спит" в `delay()`, останавливается вообще всё на плате.
Используйте неблокирующий таймер на `millis()` (или конечный автомат
для более сложных сценариев) — рабочий пример есть в
[`src/modules/sensors/sensors.cpp`](src/modules/sensors/sensors.cpp), а
разбор самой техники с кодом — в docs/architecture.md (ссылка ниже).

Подробное объяснение, список того, что считается блокирующим, и что
делать, если задача правда не влезает в неблокирующий тик — в
[docs/architecture.md](docs/architecture.md#блокирующие-операции-delay-и-почему-его-нельзя).

## CI

На каждый push и Pull Request автоматически запускаются проверки
(`.github/workflows/`):

- **Build firmware** — собирает прошивку через PlatformIO. Должна быть
  зелёной — значит, проект реально собирается, а не только "работает у
  меня локально". Arduino IDE-путь эта проверка не покрывает (см.
  [Arduino IDE vs PlatformIO](#arduino-ide-vs-platformio)).
- **AI Code Review** — автоматический ревью диффа PR, оставляет
  комментарии. Это помощник, а не замена человеческому ревью — не
  игнорируйте, но и не считайте истиной в последней инстанции.

## Git и GitHub: как мы работаем

Если вы впервые работаете с git — читайте этот раздел внимательно и не
торопитесь, это самый важный инструмент разработчика, важнее конкретного
языка программирования или IDE.

**Важно:** в репозитории **не настроены роли и права доступа** —
ограничение политики GitHub. Это значит, что технически git/GitHub
не помешает вам запушить прямо в `main` или в
чужую ветку. Это не значит, что так можно — это значит, что
ответственность за соблюдение правил ниже лежит на каждом лично.
Внимательно смотрите, в какой вы сейчас ветке (`git branch` покажет
текущую, она отмечена `*`), прежде чем пушить.

### Первоначальная настройка

```sh
git clone <URL-репозитория>
cd feeder-for-students
cp src/core/config_local.h.example src/core/config_local.h
```

### Одна ветка — одна задача

Никогда не коммитим напрямую в `main`. На каждую задачу — отдельная
ветка, созданная от актуального `main`:

```sh
git checkout main
git pull
git checkout -b display/qr-screen
```

Имя ветки — коротко и понятно, по смыслу задачи, например
`display/qr-screen`, `dispenser/stepper-driver`, `docs/architecture-fix`.

Также отмечу: одна ветка — один человек! Если в одной ветке работают
несколько людей это приводит к большому количеству конфликтов.

### Коммиты

Коммитьте небольшими логическими шагами — так проще ревьюить и проще
откатить один шаг, если он окажется неудачным. Сообщение коммита —
по делу, не "фикс"/"правки":

```sh
git status     # посмотреть, что реально изменилось
git add .      # добавить все файлы в stage
git commit -m "display: добавить отрисовку QR-кода"
```

Не делайте `git add .`/`git add -A` не глядя — легко случайно
закоммитить чужие временные файлы, файлы сборки или секреты
(`config_local.h` в `.gitignore` именно для этого, но лишняя
внимательность не помешает).

### Push в свою ветку

Первый раз для новой ветки:
```sh
git push -u origin display/qr-screen
```
Дальше просто:
```sh
git push
```

### Подтягиваем свежий `main` (fetch + rebase)

Пока вы работаете, `main` может уйти вперёд — кто-то смёрджил свой PR.
Обновляйте свою ветку регулярно и обязательно перед открытием PR:

```sh
git fetch origin
git rebase origin/main
```

`rebase` переносит ваши коммиты поверх свежего `main`, история остаётся
линейной и понятной (в отличие от `git merge`, который плодит
дополнительные merge-коммиты). Если возникнут конфликты — git
остановится и покажет конфликтующие файлы:

```sh
# открыть файл, вручную оставить нужный вариант (убрать <<<<<<< / ===== / >>>>>>>)
git add <файл>
git rebase --continue
```

Если запутались — rebase можно безопасно отменить, ничего не потеряется:
```sh
git rebase --abort
```

### Push после rebase: только `--force-with-lease`, и только в свою ветку

После `rebase` история вашей ветки переписывается (меняются хэши
коммитов), обычный `git push` откажет с ошибкой. Нужно перезаписать
ветку на сервере:

```sh
git push --force-with-lease
```

`--force-with-lease` безопаснее голого `--force`: он проверяет, что
никто другой не запушил в эту ветку после вашего последнего `fetch`, и
откажется перезаписывать чужие коммиты, если такое обнаружит. Голый
`--force` такой проверки не делает вообще.

### Правила пушей — обязательно к прочтению

- 🚫 **Никогда** не пушьте в `main` напрямую — ни `git push`, ни тем
  более с `--force`. Ни разу, ни "только поправить опечатку".
- 🚫 **Никогда** не используйте голый `--force` — ни в `main`, ни в
  чужую ветку. Только `--force-with-lease`, и только в свою
  собственную ветку, в которую кроме вас никто не пушит.
- ✅ `--force-with-lease` после `rebase` в своей ветке — это нормальная,
  ожидаемая часть процесса, не бойтесь его использовать по назначению.
- Если что-то пошло не так (запушили не туда, переписали чужую историю)
  — не пытайтесь исправить это ещё более резкими командами. Сразу
  напишите лиду/мейнтейнерам в общий чат — почти всё чинится, если не
  тянуть.

### Pull Request и мёрдж

1. Когда задача готова и ветка обновлена (`rebase` на свежий `main`,
   см. выше) — откройте PR через интерфейс GitHub: `base = main`,
   `compare = ваша ветка`. Заполните описание (подставится шаблон).
2. Дождитесь CI (см. [CI](#ci)) — все проверки должны стать зелёными.
   Если что-то упало — посмотрите лог соответствующей job, поправьте,
   закоммитьте и запушьте в ту же ветку, PR обновится автоматически.
3. **Мёрджит PR только лид или мейнтейнер**, и обязательно после того,
   как CI полностью зелёный (обычно ещё и после ревью в комментариях).
   Не мёрджите свои PR самостоятельно, даже если кажется, что всё
   тривиально.
4. После мёрджа можно удалить свою ветку (кнопка появится на странице
   PR) и начать следующую задачу от обновлённого `main`.

## Роли в команде

- **Лид проекта** — определяет архитектуру и приоритеты, финально
  мёрджит PR после зелёного CI.
- Направления работы (можно совмещать, состав уточняется отдельно от

  - CAD/3D-моделирование и печать корпуса и механики
  - Электроника, пайка, сборка

## FAQ / Troubleshooting

**Ошибка линковки на Windows, что-то вроде `ld.exe: cannot open map
file`** — путь к проекту содержит кириллицу (например
`Документы`/`Downloads`). Скопируйте
[`platformio_local.ini.example`](platformio_local.ini.example) в
`platformio_local.ini` и укажите `build_dir` с ASCII-путём (см.
комментарий в файле).

**PlatformIO/Arduino IDE не видит порт платы** — см. [Драйвер
USB-платы](#драйвер-usb-платы). В Linux/WSL порт обычно называется
`/dev/ttyUSB0` или `/dev/ttyACM0`, в Windows — `COMx`.

**Заливка прошивки зависает на `Connecting....`** — зажмите кнопку
`BOOT` на плате в момент начала заливки.

**В WSL плата вообще не находится** — см. [Если работаете в
WSL](#если-работаете-в-wsl).

**Собирается в PlatformIO, но не в Arduino IDE (или наоборот)** — почти
всегда причина в библиотеке, добавленной только в `platformio.ini`, но
не поставленной в Arduino IDE (или наоборот). См. [Библиотеки](#библиотеки).

**Не понимаю, откуда взялся конфликт при `rebase`** — это нормально,
если несколько человек меняли один и тот же файл в разных PR. Открывайте
файл, ищите маркеры `<<<<<<<`/`=======`/`>>>>>>>`, решайте, какой
вариант (или оба) оставить, и следуйте шагам из [Подтягиваем свежий
main](#подтягиваем-свежий-main-fetch--rebase). Если совсем непонятно —
`git rebase --abort` и зовите на помощь в чат, это нормально.
